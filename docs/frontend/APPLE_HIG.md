# Apple HIG: правила оформления Academy UI

Зафиксировано по указанию владельца 2026-10-04 после сверки HIG и нативного UIKit. Это постоянный ориентир для разработки компонентов, а не только отчёт по одной задаче.

## Как выбирать оформление

1. Начинать с назначения элемента и нативного паттерна Apple: заголовок секции, строка со значением, навигация или команда. Затем выбирать шрифт, цвет, геометрию и поведение вместе.
2. Читать профильный раздел HIG, а не только таблицу Typography. Шкала шрифтов не определяет, какой стиль нужен конкретному компоненту.
3. Для параметров, которых нет в HIG, сверяться со стандартным UIKit/SwiftUI на целевой версии iOS. Фиксировать версию, конфигурацию и измерения. Не выдавать измерение одной версии ОС за универсальное требование Apple.
4. HTML-макет и текущее оформление библиотеки не считать доказательством нативного вида Apple. Учитывать прямые указания владельца о приоритете источников и исключениях.
5. После правки проверять реальный компонент целиком: иерархию, отступы, выравнивание, действия, светлую/тёмную тему, RTL и увеличенный текст. Наличие правильных чисел в TextStyle само по себе не подтверждает визуальное соответствие.

### Принятые решения библиотеки

Эти решения основаны на нативном паттерне; они не являются отдельными обязательными числами из HIG:

- «Изменить» у конца заголовка и «Добавить» у конца строки — 17 Regular, без оформления таблетки и лишней полужирности. Для отдельной кнопки заголовка — зона нажатия не меньше 44 × 44.
- Радиус таблицы по умолчанию 24; у её тела нет дополнительного вертикального padding. Геометрия доступна для переопределения через тему и параметры компонентов.
- Прочие поверхности и disclosure-карточки сохраняют радиус 14: изменение таблицы не должно случайно менять соседние компоненты.
- Семантические цвета берутся из темы, с адаптацией к тёмной теме и клиентским переопределениям. Не подменять их случайными серыми/синими значениями из макета.
- Disclosure indicator обозначает переход в иерархию. У команды удаления в примере он скрыт. Не добавлять стрелку к действию только потому, что строка нажимаемая.
- При крупном тексте значения и действия могут переноситься под подпись, сохраняя направленное выравнивание. Не сжимать основной текст до разрыва слов ради сохранения одной строки.
- Заголовок секции по умолчанию сохраняет регистр. Uppercase — явное переопределение, а не универсальное правило Apple.

**Не повторять ошибку:** «Мои данные» — заголовок секции таблицы. В текущем эталоне ему соответствует 17 Semibold, а не Caption 12 Regular. Нельзя брать мелкий стиль только потому, что текст расположен над карточкой.

## Шкала типографики iOS

Стандартная категория Dynamic Type — Large (default). Размер и высота строки в pt:

| Стиль HIG | Размер / строка | Обычный вес |
| --- | --- | --- |
| Large Title | 34 / 41 | Regular |
| Title 1 | 28 / 34 | Regular |
| Title 2 | 22 / 28 | Regular |
| Title 3 | 20 / 25 | Regular |
| Headline | 17 / 22 | Semibold |
| Body | 17 / 22 | Regular |
| Callout | 16 / 21 | Regular |
| Subhead | 15 / 20 | Regular |
| Footnote | 13 / 18 | Regular |
| Caption 1 | 12 / 16 | Regular |
| Caption 2 | 11 / 13 | Regular |

Emphasized-варианты могут менять вес; prominent-заголовок таблицы использует emphasized Title 3 (Bold). Таблица не предписывает одинаковый шрифт всем кнопкам, заголовкам и строкам.

В профиле `actionTitle` — emphasized Callout 16/21, `labelMedium` — emphasized Subhead 15/20, `bodyDetail` — Subhead 15/20, `footnote` — Footnote 13/18, `caption` — Caption 1 12/16. Не смешивать Caption и Footnote.

Не переносить шкалу iOS на macOS механически: в HIG основной Body для macOS — 13/16, а для iOS — 17/22. Не уменьшать весь мобильный интерфейс из-за того, что увеличенное превью на компьютере кажется крупным.

## Шрифт и доступность

- Использовать системный шрифт через платформенные API. В Academy UI — CupertinoSystemText/Display по умолчанию. Не встраивать системные файлы SF Pro в приложение.
- Поддерживать пользовательское масштабирование текста и сохранять иерархию. Проверять адаптацию расположения, переносы и доступность действий при больших размерах.
- Не считать Inter точной заменой SF Pro. Capture на macOS загружает локальный SF Pro только для проверки; на других ОС использует Inter. Headless-снимок не доказывает точность нативной растеризации на iPhone.
- Сохранять semantics: заголовок секции объявляется заголовком, действие имеет понятное имя и единственную зону активации, disabled/pending не активируются.
- Проверять Reduce Motion, контраст, тёмную тему и RTL. Настройки шрифта, цвета и геометрии должны оставаться доступными клиенту через тему.

## Проверка изменений

- Сначала сопоставить компонент с нативным паттерном и записать источник. Если нет достоверного эталона, явно обозначить предположение.
- Для таблиц проверить `packages/academy_ui/test/profile_components_test.dart`: размеры и начертания, обычный/prominent-заголовки, высоту строк, координаты действий, semantics, 320 pt, 1×/2× и RTL.
- Получить актуальные снимки через `apps/academy_ui_catalog/tool/capture_profile_components_test.dart` и действительно просмотреть их.
- При изменении общих компонентов выполнить проверки затронутых потребителей, анализ и сборку каталога. Не объявлять весь интерфейс соответствующим HIG по результатам одной проверки шрифта.
- При смене целевой версии iOS повторно проверить UIKit/SwiftUI. Обновить этот документ и эталон, не сохранять противоречащие друг другу «текущие» таблицы параметров.
- Устройства и сессии владельца не трогать для получения эталона. Созданный для проверки временный симулятор удалить после сохранения результатов.

## Источники и происхождение

- [Apple HIG: Lists and tables](https://developer.apple.com/design/human-interface-guidelines/lists-and-tables) — группировка, назначение строк и аксессуаров.
- [Apple HIG: Typography](https://developer.apple.com/design/human-interface-guidelines/typography) — шкала, иерархия, системные шрифты и Dynamic Type.
- [UIKit: prominentInsetGroupedHeader](https://developer.apple.com/documentation/uikit/uilistcontentconfiguration-swift.struct/prominentinsetgroupedheader()) — нативный prominent-паттерн.
- [Журнал реализации и сверки](../tasks/2026-10-03-yalla-profile-components/task.md) — история. Ранние значения из HTML-макета и Caption-заголовок в журнале описывают прежние решения, а не актуальную норму.
- Коммиты сверки: `c23a573` (шкала типографики), `7c7b943` (роль заголовка и сгруппированная таблица).
