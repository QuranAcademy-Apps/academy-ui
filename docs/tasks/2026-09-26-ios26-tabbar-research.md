# Сверка таббара с iOS 26 и предоставленными примерами

Дата: 26 сентября 2026. Проверены текущий код Academy UI, материалы Apple и официальный набор Apple для Figma. Поведение приложения в этом шаге не менялось.

Последующее уточнение: пользователь выбрал перенос размеров без новых эффектов. Компактный профиль обновлён по исходному коду Telegram; актуальный результат описан в [задаче геометрии](2026-09-26-telegram-tabbar-metrics.md). Таблица ниже фиксирует состояние до этого изменения.

## Вывод

Компонент пока воспроизводит часть внешнего вида. Полного соответствия нативному таббару iOS 26 нет. Прежнюю формулу «ширина по иконке и подписи» нельзя считать подтверждённым алгоритмом Apple.

В предоставленных изображениях видны панель с тремя вкладками и аватаром, панель с пятью вкладками, символы над подписями, вложенная капсула выделения, разные оттенки выделения и текста. Статичные изображения не подтверждают жесты, сворачивание, параметры анимаций или внутреннюю реализацию приложений.

## Что подтверждают источники

- Apple описывает плавающий таббар, опциональное сворачивание при прокрутке и обратное раскрытие, нижний accessory и отдельную вкладку поиска, которая раскрывается в поле. Эти возможности предоставляет `UITabBarController`; для SwiftUI есть соответствующие API. [WWDC25: UIKit](https://developer.apple.com/videos/play/wwdc2025/284/), [WWDC25: SwiftUI](https://developer.apple.com/videos/play/wwdc2025/323/).
- Liquid Glass включает преломление, адаптацию контраста к содержимому под панелью и реакцию материала на касание. Gaussian blur с фиксированным заполнением воспроизводит только часть внешнего вида. Apple рекомендует стекло для слоя навигации и управления, а таблицы оставлять в слое содержимого. [Meet Liquid Glass](https://developer.apple.com/videos/play/wwdc2025/219/).
- Внешняя и внутренняя капсулы должны быть концентричными; требуется оптическое выравнивание содержимого. [Get to know the new design system](https://developer.apple.com/videos/play/wwdc2025/356/).
- HIG описывает подписи, SF Symbols, бейджи и адаптацию расположения символа относительно подписи. Эти правила шире одного фиксированного вертикального макета. [Tab bars](https://developer.apple.com/design/human-interface-guidelines/tab-bars?changes=la_11).
- В документации `UITabBar` описаны автоматическое распределение и системная ширина, но точной формулы измерения нового таббара я не нашёл. Это API с историей с iOS 7; его текст не доказывает все внутренние детали Liquid Glass. [automatic](https://developer.apple.com/documentation/uikit/uitabbar/itempositioning-swift.enum/automatic), [itemWidth](https://developer.apple.com/documentation/uikit/uitabbar/itemwidth).

## Figma

Открыт официальный [iOS and iPadOS 26 UI Kit от Apple](https://www.figma.com/community/file/1527721578857867021/ios-and-ipados-26). В публичном просмотрщике выбрана страница **Tab Bars**: доступны примеры с разным количеством вкладок, отдельным поиском, горизонтальным расположением и состояниями элементов. Это визуальная проверка превью, а не извлечение размеров и свойств слоёв. Точные отступы, размеры шрифтов и constraints из файла пока не подтверждены.

[Документация Figma](https://help.figma.com/hc/en-us/articles/24037833895831-Get-started-with-Apple-s-UI-kit) объясняет использование официального набора и необходимость соответствующих шрифтов. Набор макетов помогает сверить геометрию; динамическое поведение проверяется на нативном компоненте. Для этой сверки использована версия 26, хотя основной каталог Apple уже предлагает ресурсы версии 27.

## Отличие примера Telegram

В открытом исходном коде Telegram используется собственный `TabBarComponent`. Он измеряет подпись с запасом по 10 pt, затем использует равные ширины, если все подписи помещаются; иначе распределяет доступное место пропорционально. Высота группы — 64 pt, внутренний отступ — 4 pt. Есть собственное перемещаемое выделение `LiquidLensView` и обработка жеста выбора. Это данные текущего исходного кода Telegram, не спецификация Apple и не доказательство версии приложения на скриншоте. [Исходный код Telegram](https://github.com/TelegramMessenger/Telegram-iOS/blob/master/submodules/TelegramUI/Components/TabBarComponent/Sources/TabBarComponent.swift#L651).

## Состояние Academy UI

Код: `packages/academy_ui/lib/src/chrome/academy_tabs.dart`, материал: `academy_chrome.dart`.

| Возможность | Состояние |
| --- | --- |
| Плавающая капсула, символ над подписью | Есть |
| Концентричные радиусы внешней панели и выделения | Есть |
| Изменяемая ширина выделения, переключение по нажатию | Есть |
| Настраиваемые цвета, обычный и компактный профили | Есть; это профили Academy UI |
| Ширины как в найденном коде Telegram | Не совпадают: сейчас используются собственные естественные ширины и сжатие |
| Аватар / произвольное изображение вкладки | Нет: `AcademyTab.icon` принимает только `IconData` |
| Отдельный символ выбранной вкладки | Нет отдельного параметра |
| Бейджи | Нет |
| Горизонтальный макет и адаптация для iPad | Нет |
| Перетаскивание выделения | Нет; сейчас только нажатие |
| Упругая линза и адаптивный контраст | Нет; есть обычное перемещение капсулы и блюр |
| Сворачивание при прокрутке | Нет |
| Отдельный поиск и нижний accessory | Нет в таббаре; самостоятельный expanding search уже есть |
| Сохранение состояния посещённых вкладок | Есть через `IndexedStack` |
| RTL, увеличение текста, Reduced Motion | Базовая поддержка есть; нативное соответствие не доказано |
| SF-шрифт в браузере | Используется fallback; точного совпадения с iOS нет |

Размеры 60/64, 22/24, подписи 11 и ограничение ширины 416 в текущей библиотеке — выбранные параметры Academy UI, не извлечённые токены Apple. Проверки геометрии при узкой ширине и увеличении текста не являются доказательством визуального соответствия iOS.

## Порядок дальнейшего переноса

1. Подтвердить размеры и шрифты на слоях официального UI Kit и нативном образце с 3/4/5 вкладками, длинными подписями и разными размерами текста. Разделить алгоритм распределения ширины и визуальную плотность.
2. Добавить произвольный значок/аватар, выбранный значок, бейдж и горизонтальный макет. Показать варианты рядом в каталоге.
3. Отдельно добавить перетаскивание выделения и состояния касания с учётом Reduced Motion; сверить на устройстве.
4. Сделать опциональными сворачивание по прокрутке, отдельный поиск и accessory. Они не обязательны для двух присланных статичных примеров.
5. Если требуется точное системное поведение на iOS 26+, рассмотреть нативный адаптер `UITabBarController`. Для общего Flutter-компонента документировать различия. Согласованный блюр 20 и непрозрачные таблицы остаются действующим контрактом; исследование не меняет его на Liquid Glass.
