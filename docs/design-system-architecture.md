# Архитектура Academy UI

## Основа

Academy UI сохраняет оформление Yalla, системную типографику Quran, Cupertino,
SF Symbols и существующий механизм модальных окон. Из
[Forui](https://github.com/duobaseio/forui/tree/e69a328c0959ae79ba2a5675916854cbf1e65d8a)
взяты принципы организации по семействам компонентов, общей обработки
взаимодействия, композиции полей и явного владения состоянием. Новые компоненты
реализованы внутри Academy UI; зависимости от Forui и его генератора тем нет.

## Структура

```text
packages/academy_ui/lib/
  academy_ui.dart             публичный API
  src/
    app/                     AcademyApp, настройки оформления
    theme/                   цвета, палитра, радиусы, отступы, типографика,
                             настройки взаимодействия, сборка темы
    foundation/
      form/                  связь управляемого значения с Flutter Form
      interaction/           состояния нажатия, клавиатура, рамка фокуса
      overlay/               привязанные к элементам всплывающие панели
      localizations/         служебные строки ru/en/ar
      layout/                отступы страницы
      scroll/                политика прокрутки
      motion/                существующие анимационные примитивы
      surface/               маска непрозрачной заливки
      table/                 контракт геометрии строк и контекст таблицы
    widgets/
      button/ text_field/ form/ select/ autocomplete/
      calendar/ picker/ slider/ tooltip/
      table/ menu/ navigation/ modal/ ...
```

`theme` задаёт семантические значения и не импортирует компоненты.
`foundation` использует тему, но не зависит от готовых виджетов.
`widgets` собирает примитивы в элементы интерфейса; `app` подключает их к
`CupertinoApp`. Предметные данные, запросы к серверу и состояние экранов остаются
в приложении. Один компонент не должен обращаться к состоянию чужого экрана.

Крупные файлы `academy_components`, `academy_controls`, `academy_navigation`,
`academy_reader_controls`, `academy_feedback_extras` разделены по семействам.
Прежние пути `src` как файлы переэкспорта удалены 2026-11-02 (их никто не
импортировал). Для приложений основной импорт не изменился:
`package:academy_ui/academy_ui.dart`.

## Тема и взаимодействие

Новые компоненты используют существующие роли цветов, отступов, скруглений и
типографики. Обычные поля и панели непрозрачные; Blur 20 остаётся свойством
навигации. `AcademyThemeData.copyWith` позволяет локально переопределить часть
темы. Тема над Navigator обновляет и открытые модалки; popover наследует живую
тему своего якоря через `OverlayPortal`.

Материал blur — один clipped BackdropFilter с композицией фильтров изображения:
blur sigma 20 → saturation → коррекция яркости. У `BoxDecoration` такого
компонента нет `color`; отдельный слой белого/тёмного цвета не рисуется.
Цвет панели происходит из размытого контента. Saturation по умолчанию 1.25;
сила коррекции 0.54. Для светлой темы RGB после насыщенности преобразуется
как `channel × 0.46 + 0.54`, для тёмной — `channel × 0.46`.
При силе 0 выполняется только обычное размытие. Фильтры применяются к backdrop,
не к дочерним тексту/иконкам. Альфа изображения сохраняется.

`AcademyApp.chromeBlurToneStrength`, inherited Chrome theme и локальный
`AcademyChrome.blurToneStrength` задают силу обработки. `surfaceOpacity`
умножает её. Старые имена `chromeBlurTintOpacity` / `blurTintOpacity` сохранены
как совместимые алиасы, но цветной подложки больше нет. `chromeSurface` остаётся
для flat/outlined и запаса High Contrast; его переопределение не окрашивает
обычный blur. `blurBackgroundOf` описывает цвет равномерного обработанного
backdrop и используется при подборе контрастного foreground. В High Contrast
панель получает непрозрачный `chromeSurface` без BackdropFilter.

Композиция соответствует [Flutter ImageFilter.compose](https://api.flutter.dev/flutter/dart-ui/ImageFilter/ImageFilter.compose.html)
и [ColorFilter](https://api.flutter.dev/flutter/dart-ui/ColorFilter-class.html).
Это собственный материал Academy, не нативные Liquid Glass или vibrancy.
Проверки реальных пикселей подтверждают размытие границ, обработку меняющегося
фона, отсутствие заливки и неизменный foreground в обеих темах. Клиентское
изменение `chromeSurface` специально проверяется: при обычном blur его цвет
и альфа не попадают в изображение. Глобальные/локальные параметры и capture/wrap
проверены вместе с системным повышенным контрастом.

Поля имеют собственное семейство семантических ролей:

| Роль | Назначение |
| --- | --- |
| `textFieldBackground` | Обычное поле: белое / `#1C1C1E` |
| `textFieldSecondaryBackground` | Поиск внутри панели: `#F2F2F7` / `#2C2C2E` |
| `textFieldDisabledBackground` | Отключённое поле: `#E5E5EA` / `#2C2C2E` |
| `textFieldForeground` | Введённый текст и выбранное значение |
| `textFieldSecondaryForeground` | Placeholder, подпись, помощь, крестик и иконки |
| `textFieldDisabledForeground` | Отключённые значения и иконки |
| `textFieldBorder`, `textFieldDisabledBorder` | Граница в покое и видимая граница отключённого поля |
| `textFieldFocusBorder` | Акцентная рамка фокуса, контраст не ниже 3:1 |
| `textFieldErrorForeground` | Сообщение об ошибке формы |

Эти роли общие для TextInput/TextField/Field/TextFormField, Autocomplete,
обычного SearchBar, Select/MultiSelect и picker-полей. Они не вычисляются из
карточек (`surface`), навигации (`chromeSurface`) или сегментов. Изменение
общих поверхностей через `copyWith` не меняет цвета полей. Повышенный системный
контраст рассчитывает границу относительно заливки самого поля. В покое
поле имеет скругление 12 и прозрачную рамку; фокус выделяется собственным токеном.
Popover остаётся отдельной поверхностью `surface`, а его поиск использует
`textFieldSecondaryBackground`. Поиск в навигационном Chrome сохраняет материал
и собственную коррекцию контраста.

Акцент разделён на `accentColor` (выбранный исходный цвет), `accentFill`
(заливка действия), `onAccentFill` (надпись на заливке) и `accentForeground`
(ссылки/иконки на нейтральных фонах). Тёмная тема использует соответствующие
варианты известных акцентов. Заливка корректируется только ради контраста её
надписи: светлый золотой акцент сохраняется золотым с чёрным текстом, а синий
слегка затемняется для белой надписи. Контрастный цвет ссылки не подменяет
исходный акцент и не используется для заливки кнопок. Tinted-контейнеры также
строятся от исходного оттенка темы. `primary` сохраняется как прежняя роль
акцентного foreground; для новых solid-действий используются явные роли.

`AcademyColorsData.from`, `copyWith`, `AcademyColorRole` и `withValue` сохраняют
все роли. Переопределение `accentFill` без `onAccentFill` пересчитывает контрастную
надпись; остальные независимые роли сохраняются. Изменение всего семейства
акцента выполняется через `AcademyAppearance.accent` и `colorsBuilder`, поскольку
снимок `AcademyColorsData` содержит уже разрешённые цвета, а не правила темы.
Для собственных реализаций интерфейса `AcademyColors` необходимо добавить новые
роли; старый конструктор `AcademyColorsData` допускает их отсутствие с fallback
к прежним значениям. Новые клиентские темы должны переопределять поля явно.

`semantic_field_colors_test.dart` проверяет обе темы, девять акцентов (включая
белый/чёрный), независимость от общих поверхностей, контраст, применение
к компонентам и редактирование ролей. `client_colors_test.dart` проверяет
живое обновление поля в уже открытой модалке.

Палитра следует системным ролям Cupertino: светлый сгруппированный фон
`systemGroupedBackground`, белые поверхности `secondarySystemGroupedBackground`,
нейтральные серые уровни в тёмной теме, `label`/`secondaryLabel` и `separator`.
Текстовые пары корректируются для читаемости. Акцент по умолчанию — системный синий.

Сегменты обоих размеров и компактные круглые кнопки используют отдельную
непрозрачную роль `segmentBackground`: `#E1E3E7` в светлой теме и `#3A3A3C` в
тёмной. Выбранный сегмент — `segmentSelected`: белый / `#636366`.
Эти заливки не вычисляются из `surface`, фона страницы, акцента или стиля Chrome.
Изменение общих поверхностей не должно менять цвета компактных контролов.
Клиент может явно переопределить обе роли через `colorsBuilder`.
`compact_control_colors_test.dart` закрепляет цвета, непрозрачность, читаемость
и применение ролей после живой смены поверхности, акцента и стиля панелей.

`AcademyInteractionTheme` задаёт явный режим `touch` или `desktop`:

- `touch` по умолчанию: минимальная высота нового `AcademyTappable` — 44,
  адаптивный Select открывает модалку;
- `desktop`: минимальная высота — 32, Select открывает popover;
- ширина окна сама по себе не переключает режим ввода;
- `hapticsEnabled` и `selectionFeedback` управляют явными вызовами обратной связи
  библиотеки (stepper, перетаскивание, menu anchor). Собственное поведение нативных
  Cupertino-виджетов не перехватывается.

`AcademyTappable` даёт `hovered`, `pressed`, `focused`, `selected`, `disabled`,
действия Enter/Space, семантику и рамку клавиатурного фокуса. Нативные Cupertino
кнопки сохраняют свою реализацию. `AcademyPopover` поддерживает Escape, закрытие
снаружи, возврат фокуса, привязку при прокрутке, ограничение краями и учёт
клавиатуры. Произвольный длинный контент панели должен сам предоставлять прокрутку.

Стандартные кнопки используют общий `AcademyPressEffect` поверх Cupertino:
отклик начинается при контакте, масштаб до 0.97 с ограничением уменьшения
длинной стороны 5 пунктами, нажатие/возврат по 100 мс. Это отдельный эффект
отрисовки: он не добавляет распознаватель жестов, не меняет layout/hit-test и не
дублирует действие. Отмена, прокрутка, отключение кнопки и Reduce Motion
сбрасывают масштаб. Контроллер анимации принадлежит эффекту и освобождается с ним.
Параметры сверены с [Forui FTappable](https://github.com/duobaseio/forui/blob/main/forui/lib/src/foundation/tappable/tappable.dart).

`matchAnchorWidth` выбирает фактическую ширину якоря, а не фиксированные 320.
Select и Autocomplete включают эту настройку. `anchorKey` позволяет выбрать
внутренний элемент: у Autocomplete это область редактирования без внешних
отступов и текста ошибки. Положение/ширина проверяются при изменении размера и в RTL.

## Значения и время жизни

`AcademyModalHeaderBehavior` задаёт отношение контента к верхнему бару:
`separate`, `fade`, `overlay`. Контентные шиты используют `fade` по умолчанию,
формы и picker сохраняют `separate`. В режиме под баром viewport начинается от
верхнего края шита; `AcademyModalContentInsets` передаёт высоту бара в верхний
padding списка. Таким образом, первая строка изначально не перекрыта, но при
прокрутке проходит под заголовком. Длина перехода настраивается отдельно.
Градиент использует текущий `surface`, не создаёт `ShaderMask` над всем списком
и не перехватывает события. Shape clip без `saveLayer` ограничивает верхние углы;
бар не пропускает нажатия к перекрытым строкам. Вложенные страницы наследуют
настройки корневого шита и могут их менять явно. Это реализация Academy,
согласованная с фейдом основного верхнего бара; нативный variable blur iOS 26
не используется. [Apple описывает scroll edge effects](https://developer.apple.com/design/human-interface-guidelines/scroll-views)
как переход между движущимся содержимым и закреплёнными панелями.

`Select`, `MultiSelect`, календари, picker и slider управляются приложением:
`value`/`values` → отображение, `onChanged` → запрос изменения. Если родитель
отклоняет изменение, компонент не сохраняет альтернативное значение.

`AcademyFormField<T>` добавляет `validator`, `onSaved`, ошибки и autovalidation
к управляемым значениям. Изменение значения родителем не считается пользовательским
редактированием. Пользовательский запрос сначала передаётся родителю; в конце
кадра `Form.onChanged` видит принятое значение после перестроения. Это позволяет
вызывать `Form.save()` или `validate()` из `Form.onChanged`. Отклонённый запрос
отмечает взаимодействие, но не подменяет значение родителя. Несколько запросов
за кадр объединяются в одно уведомление; reset отменяет ожидающее уведомление.
`Form.reset()` запрашивает исходное значение через `onChanged`;
родитель должен принять его. Коллекции передавайте как снимки, не изменяя их на месте.

`AcademyTextFormField` работает с Flutter `Form` и `TextEditingController`.
Внешние контроллеры и FocusNode освобождает приложение. Компонент освобождает
только созданные им ресурсы. То же правило действует для контроллера popover.
При переходе от внешнего текстового контроллера к внутреннему сохраняется весь
`TextEditingValue`, включая выделение и composing; внешний объект не освобождается.

Autocomplete сохраняет доступ к якорю при открытых подсказках: очистка и
перемещение курсора работают с первого касания. Внешний тап закрывает панель
и доходит до страницы. Остальные popover по умолчанию поглощают внешний тап;
неблокирующий режим задаётся через `consumeOutsideTaps: false`.

Модальный MultiSelect хранит черновик до «Готово», отмена его отбрасывает.
В popover выбор применяется сразу. Одиночный Select применяет выбранный вариант
сразу в обоих режимах. Поля даты и времени применяют результат после «Готово».

## Поиск и даты

Select поддерживает локальные варианты с заголовками групп, описаниями,
иконками и отключёнными строками. `loader(query)` подключает асинхронный источник:
задержка поиска 200 мс, загрузка, пустой результат, ошибка и повторная попытка.
Устаревший ответ не заменяет результат нового запроса. Завершение запроса после
удаления компонента игнорируется; отменять сетевой транспорт должен сам источник.

Для удалённых значений передавайте выбранные варианты в `options` или задавайте
`labelFor`: названия остаются доступными после закрытия результата поиска.
Без форматтера отсутствующее значение отображается через `toString()`.
Autocomplete допускает свободный текст; Select ограничивает выбор вариантами.
Пустое состояние локализовано; `emptyMessage`/`emptyHint` позволяют пояснить следующий шаг.
`placement` задаёт предпочтительную сторону панелей и подсказок, с переносом при
нехватке места и учётом RTL/клавиатуры.

Календари григорианские, неделя начинается с понедельника. Дата представлена
календарными годом/месяцем/днём без преобразования часового пояса; дни строятся
календарной арифметикой. `AcademyDateRange` нормализует границы и запрещает обратный
порядок; диапазон не может включать запрещённый предикатом день. Локальный незавершённый
выбор сбрасывается при изменении внешнего диапазона или ограничений.
`AcademyTime` содержит только часы и минуты; поле использует 24-часовой выбор.
При крупном тексте календарь допускает горизонтальную прокрутку, сохраняя цели касания.
Высота навигационного текста и сегментов учитывает разрешённый шрифт, масштаб
и клиентскую высоту строки. Локальные Directionality/TextScaler сохраняются
при открытии модалки; без локального переопределения системные изменения
продолжают поступать из Navigator. Имя закрытия барьера берётся из локализации.
Обычный, диапазонный и линейный календарь имеют собственную поверхность `AcademySurface`.
Кнопка очистки ввода использует `xmark.circle.fill` и сохраняет зону нажатия 44×44.

Модалки по умолчанию имеют один detent. Дополнительные высоты задаются явно:
короткий контент — своя высота, дата/время и подтверждения — компактная высота
по содержимому, длинный список — medium/large, раскрываемая форма — medium/full.
`expandOnFocus: false` запрещает автоматическое раскрытие коротких модалок.

## Каталог и проверка

Текущий каталог сохраняет четыре вкладки владельца: «Каталог», «Quran»,
«Модалки», «Оформление». `CatalogIndex` в `catalog_pages.dart` открывает разделы
`CatalogSection`, примеры `AdvancedCatalogSection` и страницу профиля/поездок.
Тесты каталога проверяют эти переходы и независимость вкладок.

Редакторов радиусов, отступов, цветов и типографики в приложении нет. Стандартные значения библиотеки
сохраняются; «Оформление» управляет темой, акцентом, стилем навигации,
пропорциями таббара и примером клиентской палитры.

Новый компонент демонстрируется в соответствующем разделе каталога.
Quran, профиль, формы, выбор даты, перетаскивание и модальные потоки показывают
композицию компонентов. Эти проверки не подтверждают нативный VoiceOver.

[Актуальная карта API, ролей и совместимости](design-system-reference.md).

[Снимок реальных компонентов в обеих темах](previews/forui-adapted-components.png).
Его воспроизводит `packages/academy_ui/tool/capture_adapted_components_test.dart`;
для снимка без окна используются Inter и упакованные SF-иконки.

Контрактные тесты покрывают отклонённые изменения, сброс формы, владение
контроллерами, гонки поиска, отмену/подтверждение модалок, клавиатурный выбор,
границы popover, смену темы, RTL и увеличенный текст. Нативная клавиатура и
VoiceOver на физическом устройстве требуют отдельной проверки.

Тосты закрываются вертикально к краю появления: верхний — вверх, нижний — вниз.
Удержание приостанавливает таймер, перемещение ограничено направлением и 96 пунктами.
Противоположный/горизонтальный свайп не закрывает тост, короткий медленный свайп
возвращает его на место. Замена сообщения сбрасывает жест предыдущего тоста.

Результаты проверок конкретной ревизии хранятся в датированном отчёте в
`docs/reviews`, а не служат постоянным числом тестов. После изменения общей
библиотеки запускаются анализ и тесты библиотеки/каталога, сборка и применимые
снимки в обеих темах, с крупным текстом и RTL.

## Контракты семейств после ревизии

Радиусы `table`, `surface`, `disclosure` независимы: 24/14/14 по умолчанию.
`pillButton` имеет собственные радиус 30 и отступы 16×4; `menuButton` не меняет
таблетки. `pillIconExtent` и `actionIconExtent` не зависят от table/timeline.
Основные подписи строк таблицы используют `bodyRow`; заголовок — `bodyStrong`
или `sectionHeading` при prominent. Старые похожие роли не удалены и не
объявлены алиасами: клиентские переопределения остаются независимыми.

Таблица обращается к `AcademyTableRowGeometry`, а не к классам готового меню.
`AcademyTableRowLayout` позволяет сообщить inset своей строки. Маска поверхности
лежит в foundation и не импортирует modal engine; прежний modal-путь удалён. Общий resolver кнопок остаётся внутренней реализацией.

`AcademyGroupedTable` предназначен для коротких настроек и форм. `scrollable: true`
строит секции по запросу; строки отдельной секции создаются заранее в Column.
Для большого списка приложение использует builder/sliver и измеряет стоимость
на целевом устройстве. Преждевременного builder API в этой ревизии не добавлено.
