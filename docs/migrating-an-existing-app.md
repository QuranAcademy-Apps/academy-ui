# Перенос существующего приложения на Academy UI

Опыт переноса приложения Quran (`quran_flutter`, ~1100 файлов, `cupertino_ui`) на этот пакет. Документ — чек-лист и список граблей для следующих приложений (Yalla, Zikro и других). Цель переноса была жёсткой: **внешний вид и поведение приложения не меняются**.

## Короткий итог

- Чистые, самодостаточные виджеты переносятся копией с явными параметрами цвета: вид идентичен по построению.
- Виджеты с другой *архитектурой* (модалка, тост, chrome, таблица) заменой имён не переносятся. Их либо переносят целиком как есть (`lib/quran_compat/`), либо переписывают вызовы.
- Самая дорогая грабля — **две разные библиотеки Cupertino** (см. ниже). Она проявляется только на тёмной теме и RTL и не видна в обычных тестах.
- Параллельно держите в приложении тонкий **адаптер** на каждый перенесённый виджет (цвета приложения, строки, логика), а не переписывайте сотни вызовов.

## Порядок переноса

1. Подключить пакет **git-зависимостью с закреплённым `ref`** (SHA коммита). Пока идёт итерация по двум репозиториям, временно используйте `path: ../academy-ui/packages/academy_ui`, но перед завершением слоя пушьте пакет и возвращайте `ref`. Git-зависимость читает только запушенные коммиты.
2. Мост темы: собрать `AcademyColors` из палитры приложения (`academyColorsFrom`), `AcademyTypographySettings` с кривой трекинга приложения, поместить `AcademyTheme` над Navigator (в `builder` приложения), не заменяя `CupertinoApp` приложения на `AcademyApp`.
3. Иконки, motion-примитивы, простые контролы (переключатель, кольцо, сегменты, stepper).
4. Модалки, тосты, таблицы, chrome — по одному, с проверкой на устройстве.
5. Удалить временные леса (twin-тесты, legacy-копии, шимы) только после решения, какой вариант основной.

## Грабли и решения

### 1. Две Cupertino: `package:flutter/cupertino.dart` и `package:cupertino_ui`

Academy UI построен на SDK-Cupertino (`flutter/cupertino.dart`). Приложение на `cupertino_ui` имеет **другие классы** `CupertinoTheme`, `CupertinoButton`, `CupertinoSwitch`, `CupertinoApp`.

Последствия:
- Виджеты пакета читают `CupertinoTheme` из SDK. Если приложение его не предоставляет, динамические цвета (`CupertinoDynamicColor`), `CupertinoButton`, `CupertinoSwitch` берут **яркость системы**, а не выбранной темы приложения. Симптом: на выбранной в приложении светлой теме при тёмной системе контролы тёмные, или наоборот. В тестах заметно только на комбинации «тёмная тема + RTL», потому что остальные комбинации совпадают случайно.
- Тесты, которые ищут `find.byType(CupertinoSwitch)` / `CupertinoButton` по типу из `cupertino_ui`, перестают находить контрол из пакета.

Решение:
- В `builder` приложения добавить зеркало темы для SDK: `sdk.CupertinoTheme(data: sdk.CupertinoThemeData(brightness, primaryColor, scaffoldBackgroundColor, barBackgroundColor, textTheme))` с теми же значениями, что и тема `cupertino_ui`. Данные темы кэшировать (см. п. 6).
- В тестах использовать `import 'package:flutter/cupertino.dart' as sdk show CupertinoSwitch, CupertinoButton;` или общий finder, который принимает оба типа.
- Если приложение целиком на `cupertino_ui`, `lib/quran_compat/` использует `cupertino_ui` и работает только в таком приложении. Полный переход пакета на `cupertino_ui` затронул бы все остальные приложения (Zikro ~23 файла, Yalla ~138) и решается отдельно.

### 2. Кривая трекинга шрифта

У системного шрифта SF тонкая настройка `letterSpacing` по размеру. У пакета и у приложения опорные точки разные (10 против 4), у крупных заголовков пакет ставил −0,6.

Решение: `AcademyTypographySettings(tracking: функция)` — своя кривая для всех ролей, включая крупные. Значения по умолчанию не менялись.

### 3. `AcademySfIcon`: масштаб текста, зеркалирование, семантика

По умолчанию символ не следует системному масштабу текста, а `back`/`forward` в RTL подменяются. Приложение, где иконки масштабируются вместе с текстом и в RTL рисуются шрифтом, получило визуальный сдвиг.

Решение: параметры `scaleWithText: true` и `mirrorInRtl: false`; в приложении — адаптер `AppSfIcon`, который их ставит. Иконки без `semanticsLabel` пакет исключает из семантики (раньше VoiceOver читал символ приватной области Unicode).

### 4. Сопоставление цветов (мост палитры)

`AcademyPalette` заполняет роли по умолчанию; роли, которых в палитре приложения нет, остаются «чужими» цветами. Что нужно сопоставить, чтобы стандартные виджеты выглядели как в приложении:

| Роль Academy | Примечание |
| --- | --- |
| `scaffoldBackground`, `surface`, `surfaceContainerHighest` | фон страницы, карточки, вторичная заливка |
| `onSurface`, `onSurfaceVariant` | основной и вторичный текст |
| `outline`, `outlineVariant` | разделители |
| `accent*`, `primary` | акцент |
| `segmentBackground`, `segmentSelected` | **обязательно**, иначе сегменты белые на светлом фоне |
| `textField*` | заливка и текст поиска и полей |
| `modalBarrier` | **не сопоставлять**, если модалки приложения рисуют свой барьер |

Радиусы и отступы, которые отличаются у приложения (например, поиск 40 pt и радиус 10), задаются темой: `AcademyRadii(search: 10)`, `AcademyPaddings(search: ...)`.

### 5. Строки

`AcademyLocalizations` знает только ru/en/ar. Для остальных языков подписи доступности ("Information", "Close search") будут английскими. Если приложению нужны другие языки, передавайте подписи параметрами (`retryLabel`, `semanticLabel`) или регистрируйте свой делегат раньше `AcademyLocalizations.delegate`.

Делегат строк приложения должен возвращать `SynchronousFuture`. Асинхронный делегат (`async`) останавливает `Localizations` до следующего кадра: в приложении это лишний кадр, в тестах — виджеты не появляются вовсе (массовые падения «Found 0 widgets»). Используйте `loader(locale).then(...)` поверх `SynchronousFuture`, а не `await`.

### 6. Кэш данных темы

`AcademyTheme.updateShouldNotify` сравнивает данные по ссылке. Если собирать `AcademyThemeData` в `build` корня, то при любой перерисовке (изменилась настройка, язык) оповещаются все виджеты пакета. Создавайте данные темы в `State` и пересоздавайте только при смене палитры или яркости. То же для SDK-темы.

### 7. Конфликт зависимости `stupid_simple_sheet`

Пакет зависит от своей локальной копии (`path: third_party/stupid_simple_sheet`). Если приложение тоже использует `stupid_simple_sheet` (путь на свою копию), `pub get` падает: «stupid_simple_sheet from git» против «from path». Если исходники копий идентичны (проверьте `diff -r`), добавьте `dependency_overrides` на копию приложения. Если нет — сначала сведите патчи (у Quran патч `RouteSnapshotMode.animatingAndScrolling`).

### 8. Шрифт Inter в сборке

Шрифт, объявленный в `pubspec.yaml` пакета, попадает в сборку **каждого** приложения (+856 КБ), даже если никто его не использует. Пакет больше не объявляет Inter; приложение, которому он нужен, объявляет его само (файл `assets/fonts/Inter.ttf` с лицензией лежит в пакете).

### 9. Модалки: другая семантика клавиатуры

Модалка пакета (`showAcademyModal`) учитывает клавиатуру: из высоты маршрута вычитается `viewInsets`, включён `originateAboveBottomViewInset`, инсеты пересчитываются на каждый статус анимации и при смене метрик. Модалки Quran этого не делают: листы остаются на месте, заливку рисует содержимое экрана (маски углов). Прямая замена меняет высоту листов при клавиатуре и вид «пустого» листа.

Пока не добавлен режим совместимости с флагами, переносите модальную инфраструктуру приложения как есть (`quran_compat`) и проверяйте на устройстве.

### 10. Тосты, таблицы, chrome — разные модели

- Тост пакета — host с императивным `show(context, ...)`; тост Quran — виджет, который сам владеет `OverlayEntry`, с действием, кнопкой закрытия и смахиванием.
- `AcademyGroupedTable`: строка 52 pt, крупный жирный заголовок секции; `GroupedTable` Quran: строка 44 pt, заголовок капсом 12 pt, больше аксессуаров (меню, переключатель+кнопка, stepper, ручка перетаскивания, ленивые строки, анимация, маски в модалках).
- Chrome: пакет — `AcademyChrome*` с темами стилей; Quran — `GradientControlChrome` с настройкой отключения прозрачности и перф-правками.

Это не заменяется подстановкой имён: нужно либо сопоставлять модели (адаптер), либо оставить обе реализации до решения, какая основная.

### 11. Бесконечная ширина (`SizedBox(width: double.infinity)`) вокруг контролов пакета

Старый код приложения часто задаёт «на всю ширину» как `width: double.infinity`. Если адаптер оборачивает контрол пакета в `SizedBox(width: double.infinity)`, внутри модального листа с вложенным Navigator после возврата со вложенной страницы остаётся недоанимированный переход (страница сдвинута, виден затемнённый край), хотя исключений нет. Падает попиксельный тест фона. Для бесконечной ширины не оборачивайте контрол: он сам занимает всё доступное место. Конечную ширину задавайте `SizedBox`.

### 12. Имена с одинаковым смыслом, но разным контрактом

`AcademyStepper` (значение, min/max) против `AppStepper` (две callback-кнопки); `AcademySegmentedControl` (высота ≥ 44) против `AppSegmented` (36); `AcademyMessageView` (простое сообщение с повтором) против `AcademyFeedback` (иконка + заголовок). Перед заменой сверяйте не имя, а геометрию, параметры и зону нажатия.

### 13. Попиксельный twin-тест не ловит ошибки зон нажатия в RTL

`AcademyStepper.actions` рисует «−» слева и «+» справа абсолютными `Positioned(left: …)`, а зоны нажатия лежали в `Row`, который в RTL зеркалится: нажатие на «−» увеличивало значение. У старого `AppStepper` Quran был тот же дефект, и пиксельный паритет его сохранял, потому что хит-зоны ничего не рисуют. Исправлено `textDirection: TextDirection.ltr` у `Row` с зонами. Для контролов с абсолютной раскладкой добавляйте тест нажатия в обоих направлениях, а не только сравнение картинок (`test/shared_controls_test.dart`).

## Методика проверки «ничего не отличается»

**Twin-тест** — временный тест, который рисует старый и новый виджет в одной оболочке и сравнивает пиксели. Матрица: все палитры × светлая/тёмная × LTR/RTL × масштаб текста 1 и 2. Оболочка: `CupertinoApp` приложения + тема пакета + зеркало SDK-темы + палитра приложения.

Подводные камни харнеса:
- Между отрисовками **размонтируйте** дерево (`pumpWidget(SizedBox.shrink())`), иначе `State` (анимации, кэши цветов) протекает из одного кадра в другой и даёт ложные расхождения.
- В тестах шрифт Ahem: все глифы — квадраты, поэтому тест видит размер, цвет и положение, но не форму значка. Для визуального просмотра загружайте шрифт SF Icons (`FontLoader('packages/flutter_sficon/sficons')`) и Roboto под именами `CupertinoSystemText` / `CupertinoSystemDisplay`.
- `Brightness.values` — `[light, dark]`, но `TextDirection.values` — `[rtl, ltr]`: порядок падений в матрице обманчив, печатайте окружение целиком.
- Переполнение (`RenderFlex overflowed`) падает как исключение: дайте сцене достаточный размер или перехватывайте.
- Контрольный тест нужен всегда: прогоните заведомо отличающуюся пару и убедитесь, что харнес видит разницу.

Для визуального сравнения пар (слева старый, справа новый) соберите картинку из двух отрисовок в одной сцене; так сразу видно, какая реализация лучше.

## Инструменты и процесс

- **Скрипт замены импортов**: заменять `import '.../<старый файл>.dart'` на `import 'package:academy_ui/academy_ui.dart' show Символ;`. Правила: искать по имени файла; оставлять в `show` только используемые символы (иначе `unused_shown_name`); не вставлять импорт в файл с `part of` — он нужен библиотеке с `part`; сохранять порядок импортов и пустые строки.
- **Не запускать `dart format` на каталоге.** Он переформатирует нетронутый код и создаёт шум в диффе; форматируйте только файлы, которые правили. Если уже сделали — восстановите файл из git и примените замену заново.
- **`part`-файлы и общие библиотеки:** при переносе в пакет сохраняйте дерево папок, тогда относительные импорты остаются рабочими; в приложении оставляйте шим `export 'package:academy_ui/quran_compat/<путь>';`. Части (`part of`) в приложении удаляются вместе с переносом.
- **Гейт коммита и guard приложения.** Хуки приложения могут запускать `architecture_guard` и анализатор на любую команду `git commit`, в том числе в другом репозитории. Перед коммитом пакета приложение должно быть зелёным.
- **Блокировка `.dart_tool/hooks_runner`.** Два одновременных запуска `dart run` / `flutter test` в одном проекте ждут общую блокировку до 5 минут и падают с `TimeoutException`. Зависший процесс (`dart run tool/architecture_guard.dart check` часами) блокирует остальные. Запускайте тесты и guard последовательно и убивайте зависшие процессы.
- **Лимиты размера файлов приложения.** Добавленные обёртки темы в корневом `builder` могут перебрать лимит строк файла приложения. Выносите их в отдельный виджет (`AcademyThemeScope`).
- **Тесты, которые проверяют внутреннее устройство** (тип painter, геометрия старого виджета), после переноса теряют смысл: заменяйте их проверками поведения.

## Перенос Yalla (2026-11-02)

Yalla — исходник большей части пакета и строится на SDK-Cupertino, поэтому грабли №1 нет.
- Мост темы встроен в `YallaTheme`: виджет кладёт рядом `AcademyTheme` и цвета навигации
  (`AcademyChromeColors`), поэтому локальные переопределения темы (модалки, профиль,
  ночной гид) сразу видны виджетам пакета, без отдельного `AcademyThemeScope`.
- Навигация Yalla (стекло, нейтральный таббар, шапка модалки с закрытием слева) перенесена
  в пакет как опции, вид Quran/Zikro по умолчанию не меняется.
- Старые файлы chrome в приложении стали реэкспортами пакета; вызовы переименованы
  скриптом `\bYallaX\b → AcademyX`. Остаток (кнопки CTA, таблицы, модалки, меню, тосты)
  и причины — в `yalla-app/docs/tasks/2026-11-02-academy-ui-migration/task.md`.
- Кнопки: добавлена роль `actionFill` (жёлтый CTA Yalla при синем выборе), стили `neutral`
  и `plain`. Мост передаёт пакету точную типографику Yalla через `AcademyTypographySettings.styles`
  (без цвета), поэтому кнопки пакета совпали с золотыми снимками приложения пиксельно.
- Грабля: кнопка chrome пакета — граница слияния семантики. Соседние элементы без своего узла
  начинают сливаться с текстом; кнопки пакета теперь `container: true`.

### Yalla: модалки

- Владелец выбрал модель листа пакета, а не перенос листа Yalla: содержимое полной высоты,
  прокрутки и закреплённые элементы добавляют `ModalSheetScrollInsets.of`, заливки фона —
  `ModalSheetMaskedFill`, иначе содержимое рисует квадратные углы поверх скругления.
- `showAcademyModal` в приложениях раньше не использовался (Quran держит свои модалки в
  `quran_compat`), поэтому его баги не были видны: высоты при safe area сверху, Reduce Motion,
  раскрытие от фокуса вложенного Navigator, safe area под клавиатурой. Тесты пакета шли без
  safe area — добавляйте его в тесты модалок (`FakeViewPadding(top: 59, bottom: 34)`).
- Тема приложения должна быть `InheritedTheme`, иначе лист пакета (захватывает темы при
  открытии) потеряет локальные варианты темы.
- Тестовые помощники с одним шагом `pump(600ms)` после нажатия не дожидаются листа: пружина
  отсчитывает время от первого кадра после открытия.

### Yalla: меню и тосты

- `AcademyMenuItem` построен на `cupertino_ui`; в SDK `CupertinoMenuAnchor` он не работает как
  запись меню. Переводите якорь (`AcademyMenuAnchor`) и элементы вместе; тесты, которые ищут
  `CupertinoMenuItem`/`CupertinoMenuAnchor` из SDK, нужно перевести на типы пакета.
- `AcademyMenuAnchor` сам даёт хаптику открытия — уберите явный `onOpen` с хаптикой.

## Что остаётся в двух реализациях

Модалки, тосты, chrome, таб-бар, таблица, цвета (`AppColors`/`AcademyColors`), типографика. Решение по каждой паре и план — в журнале задачи приложения Quran (`docs/tasks/2026-11-01-academy-ui-migration/task.md`).
