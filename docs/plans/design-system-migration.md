## Решение по источникам

1. Темы, типографика, кнопки, поля, обычные списки, SF-иконки, панели, тосты и базовые состояния берём из Yalla.
2. Маршрут модалки, высоты, вложенную навигацию, поведение фокуса, поворот экрана и маскирование углов берём из Quran.
3. Оформление модалки подключаем к единой теме Zikro. Не переносим параллельно отдельный механизм `showYallaModal`.
4. Делаем одну публичную точку открытия `showAcademyModal<T>` и общий `AcademyModalScaffold`. Подтверждения, формы, подсказки и вложенные страницы используют её.
5. Короткий выбор рядом с кнопкой остаётся anchored menu, как в Yalla. Модалки — для содержимого и отдельных задач.

Это предлагаемая структура реализации, а не уже внесённое архитектурное изменение.

### Параметры оформления, которые сохраняем

- Базовый акцент Yalla `#263E59` — временный стартовый пресет, пока не выбран бренд Zikro. Цвет задаётся токеном и заменяется централизованно.
- Светлая основа `#F5F4F1`, текст `#171D26`, поверхности `#FFFFFF` / `#F0F0EE`; тёмные поверхности `#222936` / `#30363E`.
- Текст 17 / 15 / 13; заголовки 22 / 28, крупный navigation title 32. Системное масштабирование сохраняется.
- Кнопка: минимум 44 × 52, радиус 14. Chrome-действие: область 44 × 44.
- Grouped-строка: минимум 48, горизонтальный inset 16; поверхность: радиус 14. Информационная карточка: padding и радиус 20.
- Между смысловыми секциями 24; интервал имеет одного владельца.
- Панели: Soft, Chrome, Blur; blurSigma = 20 по уточнению владельца. Blur применяется только к навигационным chrome-кнопкам, капсулам управления и таббару. Таблицы, строки, карточки, поля, поиск, статусы и содержимое модалок остаются непрозрачными; глобальное наследование blur на эти компоненты запрещено. Без Liquid Glass.
- Поиск имеет отдельную непрозрачную заливку `surfaceContainerHighest` и читаемый placeholder `onSurfaceVariant`, в том числе на светлой поверхности модалки.
- Шрифт Inter берём вместе с подходящей лицензией; арабский шрифт отдельно выбираем по продуктовой задаче.

В исходном коде размеры не полностью централизованы: например, `YallaTokens.controlRadius = 16`, а `YallaButton` использует 14. При переносе создать токены по ролям (`buttonRadius`, `fieldRadius`, `groupRadius`), сохранив фактический внешний вид. Не подменять все размеры одним радиусом.

## Принятая структура общей библиотеки

```text
packages/academy_ui/
  lib/academy_ui.dart              # публичный импорт
  lib/src/                        # theme, appearance, components, controls
    chrome/                       # навигация и таббар
    modal/                        # маршрут, detents, focus, masked fills, flow
    motion/
  assets/fonts/                   # Inter + OFL
  third_party/stupid_simple_sheet/ # локальная версия из Quran + MIT
  test/                           # контракты и адаптированные тесты Quran
  example/                        # отдельное приложение-каталог
  README.md
  SOURCE_MANIFEST.json
```

По следующему указанию владельца UI вынесен в отдельный пакет вместо app-local DS.
Общее имя `Academy*` позволяет применять библиотеку в следующих приложениях.
Хранение настроек передаётся через интерфейс; SharedPreferences используется только
примером. Библиотека не зависит от абсолютных путей исходных проектов.

Владение состоянием:

- App создаёт контроллер оформления и store; выбранные режим, акцент и оформление панелей живут весь срок приложения.
- Виджеты DS получают значения и callbacks, не читают продуктовые preferences/API.
- Поле/поиск владеет только своими локальными lifecycle-объектами; внешний controller остаётся у передавшего его владельца.
- Маршрут модалки владеет detent controller; modal flow — вложенным Navigator; страница — своими полями и прокруткой.
- Theme/chrome доступны над корневым Navigator. Проверить смену темы и пользовательского акцента при уже открытой модалке; одного `InheritedTheme.captureAll` недостаточно считать гарантией для произвольного `InheritedWidget`.
- Не выбирать заранее BLoC, Riverpod, GetIt, router или генераторы моделей: для основы достаточно локального состояния и стандартного Navigator.

## Зависимости и решения перед реализацией

Минимальные кандидаты по изученному коду: Flutter SDK, `flutter_sficon`, `shared_preferences`, `cupertino_ui` и локальный `stupid_simple_sheet` с его транзитивными зависимостями. Точные версии и совместимость проверить при создании каркаса; не копировать весь pubspec Quran. У локального sheet-пакета заявлены Dart >= 3.12 и Flutter >= 3.44, у Yalla — Dart ^3.13.2.

Владелец принял план и разрешил реализацию общей библиотеки. Платформы, bundle IDs и окончательный бренд пока не определены; до их уточнения можно готовить общий Dart/UI-слой, но нельзя объявлять готовой нативную конфигурацию. Отдельные предметные модалки Quran потребуют явного выбора сценария, если нужны их реальные функции.

Общий UI и механизм модалок перенесены в `packages/academy_ui`; готов каталог и руководство подключения. Зависимости разрешены отдельно, без конфигураций доноров. Исходные приложения не изменялись. Результаты проверок и ограничения записаны в task-документе.
